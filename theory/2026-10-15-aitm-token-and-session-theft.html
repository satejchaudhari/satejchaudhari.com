AiTM, Token & Session Theft

2026-10-15 · 10 min read

Multi-factor authentication stopped password phishing from working on its own — so attackers stopped targeting the password and started targeting the session. Once a user has authenticated and satisfied MFA, the service issues a token (a cookie, an OAuth token, a Kerberos ticket, an Entra primary refresh token). Steal or relay that token and you are authenticated as the user without ever touching their password or their second factor. This is the defining initial-access and credential-access technique of the current era.

Why MFA is not the finish line

MFA authenticates the login event. The artefact it produces — the session token — is bearer material: whoever holds it is treated as the authenticated user until it expires or is revoked. Conditional-access policy can bind a session to a device or network, but where it does not, the token is portable. The whole class of attacks below is about getting that token.

Adversary-in-the-Middle (AiTM) phishing

A reverse-proxy phishing kit (the archetype is Evilginx) sits between the victim and the real login page. The victim sees the genuine site — because they are talking to it, through the proxy — enters their password, and completes MFA against the real service. The proxy relays every request faithfully and, on success, captures the session cookie the service sets. The operator imports that cookie and is inside the account. Because the victim authenticated to the real origin, this defeats push/OTP/SMS MFA entirely.

ElementRole in the attack
Phishing linkPoints at the proxy, not the real site
Reverse proxyRelays traffic both ways, logging credentials and the session cookie
Session cookieThe prize — replayed to ride the authenticated session

The Entra primary refresh token (PRT)

On Entra-joined Windows, the PRT is a long-lived token that silently signs the user in to cloud apps. It lives protected by the TPM, but malware running as the user can request PRT-derived cookies through the normal broker interfaces. A stolen PRT (or a PRT cookie) is an MFA-satisfied cloud session — the cloud analogue of pass-the-hash. Related tokens — refresh tokens cached by the Azure CLI, access tokens in ~/.azure — are lower-hanging fruit with the same effect.

Browser session and OAuth token theft

If you already have code execution on an endpoint, you do not need a proxy — you steal the cookies directly from the browser profile (covered in Browser Credential & Token Theft). A related, consent-based route is the illicit OAuth grant: a malicious app asks the user to approve broad delegated scopes (mail, files); the user clicks "Accept"; the app now holds a refresh token that survives password resets and most MFA, because no further interactive login is needed.

Device-code phishing

The OAuth device-code flow is meant for input-constrained devices (a TV). An attacker initiates the flow, gets a user code, and phishes the victim to enter that code at the genuine microsoft.com/devicelogin page. The victim authenticates and consents on the real site; the attacker's device receives the tokens. As with AiTM, the victim's interaction is with the legitimate service, so traditional MFA does not help.

What actually stops it

  • Phishing-resistant MFA (FIDO2 / WebAuthn / passkeys). The authenticator is cryptographically bound to the real origin, so an AiTM proxy on a different domain cannot complete the ceremony. This is the one control that breaks the whole class.
  • Token binding & conditional access: bind sessions to a compliant/managed device and a known network so a stolen cookie replayed from attacker infrastructure fails; shorten session lifetimes.
  • Continuous access evaluation: revoke sessions in near-real time on risk signals rather than waiting for token expiry.
  • App-consent governance: block user consent to unverified apps; review risky OAuth grants; disable device-code flow where unused.
  • Detection: impossible-travel and new-ASN sign-ins on an existing session, token use from an unexpected device, and sudden enterprise-app consents.
