Data Collection & Exfiltration

2026-10-09 · 9 min read

The objective of most engagements is data — proving an attacker could reach and remove it. Collection is finding and staging what matters; exfiltration is getting it out past the controls meant to stop it. For a red team the point is less the theft itself than demonstrating the path and testing whether anyone notices, which makes the detection angle central.

Collection — find and stage

  • Find it — file shares, SharePoint/Confluence, mailboxes, databases, code repos and cloud storage; search for keywords, document types and obvious crown jewels (PII, source, financials, secrets).
  • Stage it — collect to a single working location, then compress and often encrypt into an archive so the transfer is one object you control.
  • Mind the footprint — mass file access and large archive creation are themselves detectable; scope tightly rather than hoovering everything.

Exfiltration channels

ChannelCharacter
Over the C2 channelSimplest — the existing beacon carries the data; slow and ties volume to the implant.
HTTPS to a cloud serviceUpload to a sanctioned-looking SaaS/storage provider so it blends with normal traffic — a very common real-world path.
DNS exfiltrationEncode data into DNS queries; slow but egresses where little else does.
Email / collaborationSend to an external mailbox or share link where those are allowed.
PhysicalRemovable media on an on-site engagement.
The art is matching the channel to the environment's blind spot: a place that already allows large outbound transfers (a cloud backup, a sanctioned file-sharing SaaS) is quieter than a novel channel, because it hides in traffic the organisation has decided to trust.

Beating DLP and egress controls

  • Encrypt and encode so content inspection cannot match on keywords or file signatures.
  • Chunk and throttle so volume stays under thresholds and does not spike.
  • Use allowed destinations — a provider the org already permits defeats destination-based blocking.
  • Blend timing with business hours and normal traffic patterns.

Detection & defence (the real deliverable)

The value to the client is which of these the blue team catches. Defences and the signals they produce:

  • DLP on content and destinations, and egress filtering that only allows known destinations — the primary controls.
  • Volume & baseline analytics — a host uploading far more than normal, to an unusual destination, at an unusual time.
  • DNS analytics (query volume, length, entropy) for DNS exfil; see Logging.
  • Data access monitoring — mass reads of a share or mailbox, and large archive creation on an endpoint.
  • Report the gaps: which channel worked, what it would have taken to catch it, and where to add coverage — see Detection Engineering.
