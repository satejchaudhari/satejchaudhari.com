Process Injection — Concepts & Detection

2026-10-15 · 9 min read

"Process injection" names the family of techniques for getting code to run inside a process — frequently a process other than the attacker's own — to borrow its trust, its network reach, or simply to hide. For a defender and for an operator reasoning about OPSEC, the useful view is not a recipe but a map of the named techniques and the telemetry each one generates. That is what this page is: a conceptual catalogue and its detection story. It pairs with In-Memory Post-Exploitation Tradecraft and the detection material in Logging & Telemetry.

Why injection exists

  • Blending: activity inside a common, trusted process is harder to pick out than a lone unknown binary.
  • Trust inheritance: the host process may own a logon session, outbound network access, or privileges the attacker's process lacks.
  • Resilience: code hosted in a long-lived process survives the death of the initial foothold.

The named techniques, at a glance

You will see these names in EDR alerts, ATT&CK (T1055 and its sub-techniques), and malware reports. Knowing the concept is enough to recognise and hunt them:

TechniqueOne-line conceptTell-tale signal
Remote-thread injectionWrite code into another process, start a thread on itCross-process memory write + remote thread creation
APC injectionQueue code to run on an existing alertable threadCross-process APC queueing
Thread hijackingRedirect an existing thread to attacker codeThread context set from another process
Process hollowingLaunch a legit process suspended, replace its imageImage/disk mismatch; suspended-create then unmap
DLL injection / search-orderLoad a DLL into a target, sometimes via load-order gapsUnsigned/unexpected module load
Reflective / image-backed loadingMap code so it resembles a normally loaded modulePrivate executable memory, or image-backed anomalies

The signal that ties them together

Most of these end with the same observable: a region of executable memory that is not backed by a file on disk, and/or a cross-process operation (one process writing to or creating execution in another). Benign software rarely does either, so defenders and memory scanners (PE-sieve, Moneta, EDR memory inspection) treat "RX/RWX private memory" and "cross-process write + execute" as high-value hunting heuristics. Understanding that single idea explains why injection is noisy and why so much offensive effort goes into making the payload resemble normal loaded code rather than inventing new injection primitives.

Where the telemetry comes from

  • Kernel callbacks & ETW: the OS raises events on process and thread creation and on image loads — the raw material EDR correlates.
  • Sysmon: event ID 8 (CreateRemoteThread), 10 (ProcessAccess with suspicious rights), 7 (ImageLoad) are the classic injection trio. See Logging & Telemetry.
  • Memory scanning: periodic or on-signal scans for anomalous executable regions.
  • Process lineage: a trusted process spawned by an unexpected parent, or exhibiting network/behaviour it never normally shows.

Hardening and response

  • Attack Surface Reduction rules that block process-injection behaviours and credential-store access.
  • Protected Process Light (PPL) for sensitive processes such as LSASS, raising the bar on who can open and write to them — see LSASS Dumping & Credential Extraction.
  • Exploit-protection mitigations (CFG, ACG/arbitrary-code guard, blocking non-Microsoft binaries) for browsers and Office.
  • Hunt the artefact, not the API: alert on the memory and cross-process signals above, which survive changes in the specific technique used.
