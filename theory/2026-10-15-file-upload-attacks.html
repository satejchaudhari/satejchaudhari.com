File Upload Attacks

2026-10-15 · 8 min read

File-upload functionality is a perennial source of serious bugs because it lets a user put a file of their choosing onto the server's filesystem. If the application then serves or executes that file, an upload can become remote code execution; even when it cannot, uploads enable stored XSS, SSRF, path traversal, and denial of service.

The dangerous case: uploaded code that executes

The worst outcome is uploading a server-executable file (a web shell in the app's language) into a directory the web server will execute, then requesting it. Everything defenders do around uploads is ultimately about preventing that chain: controlling what is stored, where it is stored, and whether it can ever be executed or served.

Why validation so often fails

Weak checkWhy it fails
Extension deny-listAlternate executable extensions and case/trailing tricks slip through
Content-Type trustThe client sets it; it is not evidence of the real content
Magic-byte check onlyA file can be a valid image and contain code (polyglot)
Client-side validationTrivially bypassed — it is not a security control

Because every individual check can be fooled, robust upload security relies on architecture, not a single filter.

Beyond RCE

  • Stored XSS: an uploaded HTML/SVG served inline runs script in the victim's session.
  • Path traversal: a crafted filename writes outside the intended directory, overwriting config or planting files.
  • SSRF/XXE via parsers: uploaded documents processed server-side (images, XML, office files) can trigger SSRF or XXE.
  • DoS: zip bombs, pixel floods, giant files.

Detection & prevention

  • Store uploads outside the web root (or in object storage) and serve them through a handler that never executes them.
  • Serve with Content-Disposition: attachment and a correct, fixed content type; strip execution permissions.
  • Allow-list acceptable types, validate real content, and rename files to server-generated names with a safe extension.
  • Isolate processing of uploaded documents; keep parsers patched and sandboxed.
  • Detection: new executable files appearing in web directories, and requests to recently uploaded paths.
