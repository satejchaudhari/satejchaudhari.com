File Upload Attacks

2026-10-15 · 8 min read

File upload is a perennial source of serious bugs because it lets a user place a file of their choosing on the server's filesystem. If the application later serves or executes that file, an upload becomes remote code execution; even when it cannot, uploads enable stored XSS, path traversal, SSRF via parsers, and denial of service.

The worst case: upload code that executes

The classic chain is uploading a server-executable file into a directory the web server will run, then requesting it:

# a minimal PHP web shell, uploaded as shell.php, then:
GET /uploads/shell.php?c=id      →  runs `id` on the server

Everything defenders do is about preventing that chain — controlling what is stored, where, and whether it can ever be executed or served inline.

Why single checks fail

Weak checkBypass
Extension block-list.phtml .php5 .pht .phar, case tricks, trailing dot/space
Content-Type trustClient sets it — send image/png with PHP body
Magic-byte check onlyPolyglot: valid GIF header + code (GIF89a;<?php …)
Double extensionshell.php.jpg on misconfigured Apache
Null byte (legacy)shell.php%00.jpg
Client-side validationNot a control — bypass in the proxy

Because each individual filter can be fooled, robust upload security relies on architecture, not one check.

Beyond RCE

  • Stored XSS — an uploaded .html/.svg served inline runs script in the victim's session.
  • Path traversal — a crafted filename (../../var/www/shell.php) writes outside the intended folder.
  • SSRF / XXE via parsers — server-side image/XML/office processing can be steered to fetch internal URLs (see SSRF).
  • DoS — zip bombs, decompression bombs, pixel floods.

Prevention

  • Store uploads outside the web root (or in object storage) and serve them through a handler that never executes them.
  • Serve with Content-Disposition: attachment and a fixed, correct Content-Type; strip execute permissions.
  • Allow-list the acceptable types, validate the real content, and rename to a server-generated name with a safe extension — never trust the uploaded name.
  • Isolate and patch the libraries that parse uploaded documents.
  • Detect new executable files appearing under web directories and requests to freshly uploaded paths.
