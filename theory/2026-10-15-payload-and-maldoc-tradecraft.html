Payload & Maldoc Tradecraft

2026-10-15 · 10 min read

Once a lure is clicked or an attachment opened, something has to run and call home. "Maldoc tradecraft" is the craft of getting that first execution past a hardened, patched, EDR-monitored endpoint — and it is a moving target, because every technique that works at scale gets a control built against it. This page traces the evolution: what each delivery format is, why it worked, and what killed it. The point is to understand which control you are testing.

The arms race in one table

EraVectorWhat ended it
ClassicVBA macros in .doc/.xls from emailMacros-from-internet blocked by default (2022)
ReactionContainer files: ISO/IMG/VHD hiding a payloadMark-of-the-Web now propagates into mounted contents
ReactionLNK + script, OneNote embedded files, HTML smugglingLNK/OneNote detections; download-protection
CurrentTrusted installers (MSI/MSIX), signed binary sideloadingApp control (WDAC), reputation, SmartScreen

Mark-of-the-Web: the hinge

Almost every defensive advance here rests on one mechanism. A file downloaded from the internet is tagged with a Mark-of-the-Web (MotW) — a zone identifier in an alternate data stream. Office opens MotW-tagged documents in Protected View and refuses their macros; SmartScreen checks MotW binaries against reputation. You can see the mark directly:

# PowerShell — is the file marked as internet-sourced?
Get-Content .\invoice.docm -Stream Zone.Identifier
# → [ZoneTransfer] / ZoneId=3   (3 = Internet)
# remove it (what a victim "unblocking" a file effectively does)
Unblock-File .\invoice.docm

The entire container-file wave existed to break MotW propagation: historically, files extracted from an ISO or archive did not inherit the mark, so the payload inside ran without restriction. Each time a format stopped propagating MotW, that format died as a vector. This one flag explains the whole timeline.

The format families

  • Office macros (VBA) — once dominant; now blocked by default for internet files. Still relevant internally.
  • Container files (ISO/IMG/VHD/ZIP) — smuggled a payload past the mark and some gateways; mostly closed by MotW propagation + ASR.
  • Shortcuts & embedded objects (LNK, OneNote) — launch a script host; heavily signatured now.
  • HTML smuggling — the payload is assembled in the browser from a JavaScript Blob, so nothing malicious crosses the network as a file.
  • Installers & signed binaries — MSI/MSIX and signed EXEs that sideload a malicious DLL, trading on trust rather than hiding.

What the first stage actually does

The document is only the wrapper. It launches a loader whose job is to get a C2 agent running in memory while evading the endpoint stack — the subject of Process Injection and In-Memory Tradecraft. It must also pass script/memory scanning (see Modern AMSI & ETW Bypasses) and, on locked-down hosts, application control (AppLocker & WDAC Bypass).

Detections and controls

  • Attack Surface Reduction (ASR) — block Office child processes, executable content from email/script hosts, and Win32 calls from macros. For example, the "block Office child process" rule: Set-MpPreference -AttackSurfaceReductionRules_Ids d4f940ab-401b-4efc-aadc-ad5f3c50688a -AttackSurfaceReductionRules_Actions Enabled.
  • Keep MotW working — ensure archive tools and mounted images propagate the mark; it is the backbone control.
  • Application control (WDAC/AppLocker) — allow-list what may execute, so an unknown loader never starts.
  • Process-lineage telemetry — winword.exe → wscript.exe → rundll32.exe is a textbook maldoc chain; Sysmon/EDR process trees catch it (see Logging & Telemetry).
  • Disable what you do not use — VBA, HTA, and the Windows Script Host are legacy execution surfaces most environments can turn off.
