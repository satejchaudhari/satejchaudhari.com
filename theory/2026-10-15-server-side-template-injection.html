Server-Side Template Injection

2026-10-15 · 8 min read

Server-Side Template Injection (SSTI) happens when user input is embedded into a server-side template that is then evaluated by the template engine. Because template engines are small programming languages, injecting into one can escalate from reflecting text to executing arbitrary code on the server. It is a common foothold on modern web apps and a frequent HackTheBox route.

Template engines are languages

Engines like Jinja2 (Python), Twig (PHP), Freemarker/Velocity (Java), ERB (Ruby) and Nunjucks (Node) expand placeholders, evaluate expressions, and call methods. If the application builds a template by concatenating user input — rather than passing that input as data to a fixed template — the user's input is parsed as template code.

The classic detection probe

The universal first test is a mathematical expression in template syntax, e.g. {{7*7}}. If the response contains 49, the input is being evaluated by the engine — a positive SSTI signal. (This is exactly the non-destructive probe the htb-recon tooling runs.) From a confirmed evaluation, the escalation path depends on the engine: expose an object that can reach the runtime, and template evaluation becomes code execution.

Jinja2 / NunjucksPython / Node{{7*7}} → 49
TwigPHP{{7*7}} → 49

Why it reaches code execution

Template languages expose object introspection — from a benign object you can often walk the object graph to reach the runtime's facilities (process calls, file access). The sandbox many engines ship is routinely escapable, which is why SSTI is treated as RCE-equivalent until proven otherwise. The conceptual fix is to never let input be the template.

SSTI vs XSS

Reflected input that renders as HTML is XSS (client-side). The same input rendering through the server's template engine is SSTI (server-side) and far more serious. The {{7*7}}→49 result distinguishes them: XSS would show the literal string, SSTI shows the computed value.

Detection & prevention

  • Pass user input as data, never concatenate it into template source; use the engine's parameterised rendering.
  • Use logic-less or sandboxed templates where possible, and keep engines patched (sandbox escapes are common CVEs).
  • Detection: template-evaluation error messages, and app servers spawning shells shortly after rendering user-influenced content.
