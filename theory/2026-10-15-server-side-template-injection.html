Server-Side Template Injection

2026-10-15 · 8 min read

Server-Side Template Injection (SSTI) happens when user input is placed into a server-side template that the engine then evaluates. Template engines are small programming languages, so injecting into one escalates from "my input is reflected" to "my input runs on the server". It is a common foothold on modern apps and a frequent HackTheBox route.

The root cause in one line

The bug is building the template from user input instead of passing user input to a fixed template:

# VULNERABLE — input becomes part of the template source
render_template_string("Hello " + name)          # Flask/Jinja2

# SAFE — input is data passed to a fixed template
render_template("hello.html", name=name)

Detect it: the 7*7 probe

Submit a tiny arithmetic expression in template syntax. If the response shows the computed value, the engine evaluated it — that distinguishes SSTI from plain XSS, which would echo the literal text.

{{7*7}}        → 49     Jinja2 (Python), Twig (PHP), Nunjucks (Node)
${7*7}         → 49     Freemarker, some Java engines
#{7*7}         → 49     Ruby / some engines
<%= 7*7 %>      → 49     ERB (Ruby)
@(7*7)         → 49     Razor (.NET)

The polyglot ${{<%[%'"}}%\ throws a distinctive error in most engines and helps fingerprint which one you are in.

From evaluation to code execution

Once the engine evaluates your input, you walk its object model to reach the runtime. In Jinja2 the classic path climbs from any object to Python's loaded modules; the exact gadget changes between versions, which is why tools exist to automate it:

# confirm the engine can reach Python internals (read, not yet RCE)
{{ config }}                         # Flask leaks the app config
{{ ''.__class__.__mro__ }}           # object hierarchy is reachable

# let a tool find the current working gadget rather than hand-building it
tplmap -u 'https://target/page?name=*'        # detect + exploit, many engines
# SSTImap is the maintained successor to tplmap

The sandboxes many engines ship (Twig sandbox, Jinja2 sandboxed environment) are routinely escapable, so treat confirmed SSTI as RCE-equivalent until proven otherwise.

Prevention

  • Never concatenate input into template source. Pass it as a variable to a pre-compiled template.
  • Prefer logic-less templates (e.g. Mustache) for user-influenced output, and keep engines patched — sandbox escapes are recurring CVEs.
  • Detect template-evaluation errors in logs and app servers spawning shells shortly after rendering user-controlled content.
