LSASS Dumping & Credential Extraction

2026-10-09 · 10 min read

The Local Security Authority Subsystem (lsass.exe) caches the secrets of everyone logged on to a Windows host — NTLM hashes, Kerberos keys and tickets, and, where protections are weak, cleartext passwords. Reading its memory is the single highest-value credential-access action on Windows, which is why both offence and defence obsess over it. This page is the mechanism; Windows Credential Storage is the background on where each secret lives.

Why LSASS is the prize

After an interactive, RDP or runas logon, LSASS holds material to authenticate as that user. Extracting it yields hashes to pass or crack, Kerberos tickets to reuse, and sometimes plaintext — a foothold account can become every privileged user who has touched the box. Dumping requires local administrator (or SeDebug), which is why it sits after a privilege-escalation step.

How it is read

ApproachIdea
Full process dumpCreate a minidump of LSASS (via built-in tools such as the task manager, a signed Microsoft utility, or the comsvcs.dll MiniDump export) and parse it offline — no attacker credential-stealer runs on the host.
Direct read toolsOpen a handle to LSASS and read its memory in place to extract secrets.
Stealthier variantsTools that avoid the obvious high-privilege handle, dump only needed regions, or produce an obfuscated dump to evade memory scanning (the arms race EDR drives).
The durable trade is: take the memory off the host and parse it elsewhere. Offline parsing (mimikatz, pypykatz) keeps the loud, well-signatured step off the endpoint; only the dump itself has to happen there, and that is what detection targets. 
# 1. find the LSASS process id
tasklist /fi "imagename eq lsass.exe"          # or: Get-Process lsass

# 2. dump it with the SIGNED comsvcs.dll MiniDump export (SeDebug / SYSTEM)
rundll32 C:\Windows\System32\comsvcs.dll, MiniDump <lsass_pid> C:\Windows\Temp\l.dmp full

# 3. parse the dump OFFLINE, on your own machine — the loud step never runs on the host
pypykatz lsa minidump l.dmp
#   mimikatz:  sekurlsa::minidump l.dmp  then  sekurlsa::logonpasswords

Dumping methods, loudest to quietest

Every method ends with the same offline parse; what differs is how much noise the dump makes. EDR watches the obvious handle-open and the well-known MiniDump call, so modern tradecraft moves down this list.

MethodHow it worksOPSEC
Task Manager / comsvcs MiniDumpRight-click → Create dump file, or rundll32 comsvcs.dll, MiniDumpLoud — both are signatured and alert on sight
Signed-binary dumpA Microsoft-signed utility (ProcDump-style) or Windows Error Reporting writes the dumpBlends with legitimate crash tooling, but the LSASS handle still shows
Handle duplication / direct syscallsnanodump duplicates an existing LSASS handle or reads memory via raw syscalls, optionally writing an invalid-signature dumpAvoids the obvious OpenProcess and can skip touching disk
Process snapshot (PssCaptureSnapshot)Clone LSASS into a snapshot and dump the clone rather than the live processThe read targets the clone, dodging handle-on-lsass rules
Kernel / BYOVD (for PPL)A vulnerable signed driver supplies the kernel read needed when LSA Protection is onPowerful but noisy — the driver load is itself high-signal

Parse it off the host

Whichever method captured the dump, copy it to your own machine and parse it there with pypykatz lsa minidump or mimikatz sekurlsa::minidump. The credential parser never runs on the endpoint, so the only on-host artefact is the dump file itself — which is why capture, not parsing, is where detection lives.

Protections that get in the way

  • LSA Protection (PPL / RunAsPPL) — marks LSASS as a protected process so normal admin handles cannot read it; bypassing it needs a kernel primitive (a vulnerable driver / BYOVD) or disabling the protection, both of which are themselves detectable.
  • Credential Guard — virtualisation-based isolation (default-on since Windows 11 22H2 / Server 2022 Enterprise) that seals NTLM secrets and Kerberos TGT keys in an isolated LSA process, so a dump no longer yields them. It does not cover DPAPI-protected secrets, tickets you can still request as the logged-on user, or the cloud Primary Refresh Token — pivot there instead of fighting it.
  • Defender ASR — a rule that blocks credential theft from LSASS.

When LSASS is off the table

If LSASS is protected, credentials still live elsewhere: the SAM/SECURITY/SYSTEM registry hives (local accounts and cached domain logons), DPAPI-protected secrets (browsers, vault, RDP — see DPAPI Abuse), NTDS.dit on a domain controller, and Kerberos tickets on disk. A SeBackup/SeRestore token (see token abuse) reads the hives directly.

Detection & hardening

  • Alert on process handles opened to lsass.exe with read/VM access by non-system processes (Sysmon event 10) — the highest-signal detection — and on minidump creation of LSASS.
  • Enable LSA Protection and, where supported, Credential Guard, plus the Defender ASR LSASS rule.
  • Block vulnerable drivers (Microsoft blocklist / WDAC) so PPL cannot be bypassed via BYOVD.
  • Reduce exposure: limit interactive/RDP logons of privileged accounts on general hosts (see Privileged Access & the EAM) so there is less to steal.
