BloodHound & AD Enumeration

2026-10-09 · 10 min read

Active Directory is too large to attack by eye. BloodHound turns it into a graph — users, computers, groups and GPOs as nodes, and the rights between them as edges — so the path from where you are to Domain Admin becomes a query rather than a guess. Learning to think in that graph is the core AD enumeration skill; the AD attack map is the catalogue of what each edge means.

Collect, then analyse

A collector gathers the directory data and writes it for the graph database to ingest. SharpHound (and the Python collector) pull sessions, local-group membership, ACLs, trusts, GPOs and more; AzureHound does the same for Entra ID / Azure. You run the collector with a domain account, import the result, and explore. 

# collect (any domain user is enough for most of the graph)
SharpHound.exe -c All
# the result imports into the BloodHound UI / graph database for querying

Nodes & edges — the mental model

Every attack technique on the site is an edge in this graph. A few that recur:

EdgeMeans
MemberOfGroup membership — inherited rights.
AdminTo / CanRDPLocal admin / RDP on a computer — a place to harvest more creds.
HasSessionA user is logged on there — steal their token/creds.
GenericAll / WriteDACL / GenericWriteControl over an object — ACL abuse to take it over.
CanPSRemote, ForceChangePassword, AddMemberSpecific abusable rights with known techniques.
Delegation / cert edgesKerberos delegation and AD CS paths.

Finding the path

The power is shortest-path: mark your owned principals, then ask for the path to a high-value target (Domain Admins, a specific server). BloodHound runs the graph query and shows the chain of edges — each one a technique you execute to move one hop closer.

The workflow is a loop: enumerate → find the shortest path → abuse the next edge → mark the new principal owned → re-query. Each hop usually corresponds to a page in the AD section here and a node in the attack map.

Custom queries

Beyond the built-in queries, Cypher lets you ask precise questions — "which users with an SPN (kerberoastable) can reach a DA group?", "which computers have unconstrained delegation?", "shortest path from kerberoastable users to high value". Writing good queries is what separates a quick win from hours of clicking.

OPSEC & detection

  • Collection is noisy: heavy LDAP queries, session enumeration and SMB connections to every host. Scope the collection, run it slowly, or use targeted methods when stealth matters.
  • Defenders detect SharpHound by its LDAP query volume and pattern, and by mass session/SMB enumeration — good content for detection engineering.
  • Honeypot objects and deceptive edges catch indiscriminate path-following.
  • On the defensive side, BloodHound is also a blue-team tool: run it on your own directory to find and cut the attack paths before an adversary does — the premise of AD Hardening & Tiering.
