AD

Active Directory Persistence

2026-10-09 · 12 min read

Host persistence dies when the endpoint is reimaged. Domain persistence does not — it lives in the directory and the Kerberos trust itself, so it survives machine rebuilds and often password resets. This is the persistence that matters once the domain is owned, and the reason recovery after a domain compromise is so painful. It builds on Kerberos Ticket Attacks, DCSync and AD CS.

Kerberos key material

TechniqueMechanism
Golden TicketThe krbtgt hash lets an attacker forge TGTs for any user — valid until krbtgt is rotated twice.
Silver TicketA service account's key forges service tickets for that one service — quieter, never touches the DC.
Diamond / Sapphire TicketModifies a real TGT rather than forging from scratch, to better survive anomaly detection.
Skeleton KeyAn in-memory patch on a DC so a master password authenticates as anyone (memory-resident; cleared on reboot).
The krbtgt hash is the crown jewel: recovering from a Golden Ticket means rotating krbtgt twice (the account retains its previous key), which many IR runbooks miss the first time.

Directory ACL & object backdoors

  • DCSync rights — granting a controlled principal the replication rights lets it re-pull every hash on demand, indefinitely.
  • AdminSDHolder / SDProp — an ACE written onto the AdminSDHolder object is re-stamped onto every protected (admin) group hourly, so backdoor rights keep returning after cleanup.
  • ACL backdoors — GenericAll/WriteDACL over key objects, or nested group membership, to re-escalate at will (see ACLs & DACLs).
  • Hidden membership — primary-group-ID tricks and SID history that enumeration overlooks.

Certificate & credential persistence

  • Stolen CA key — with the enterprise CA private key an attacker mints authentication certificates for any user, valid until the CA certificate expires (often years).
  • Shadow Credentials — writing msDS-KeyCredentialLink on a target to authenticate as it via PKINIT without its password (see Shadow Credentials).
  • DSRM — the Directory Services Restore Mode local admin on a DC aliased to domain logon.

DCShadow

DCShadow registers a rogue domain controller long enough to push arbitrary directory changes through replication — SID history, ACEs, planted attributes — without going through a real DC's normal write path, which makes it hard to see.

Detection & recovery

  • Monitor the sensitive objects: AdminSDHolder ACE changes, new replication-capable principals, msDS-KeyCredentialLink writes, and replication from non-DC sources (DCShadow).
  • Forged tickets surface as Kerberos anomalies (lifetimes, encryption types, a TGS with no matching AS request) — see Detection Engineering.
  • Recovery after domain compromise: rotate krbtgt twice, review AdminSDHolder and privileged-group ACLs, audit AD CS templates and the CA key, and treat the directory as suspect — the premise of AD Hardening & Tiering.
