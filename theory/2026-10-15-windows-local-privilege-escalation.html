Windows Local Privilege Escalation

2026-10-15 · 10 min read

You have a shell as a low-privileged user — a service account, a web-app identity, a standard domain user on a workstation. Local privilege escalation is the step that turns that into SYSTEM or local administrator, from where you can dump credentials, install persistence, and move on. On Windows the routes almost all reduce to one idea: a privileged component trusts something a low-privileged user can control. This page organises the common classes and the enumeration that finds them. It complements Windows Token Abuse & Potato Attacks (the token-centric SYSTEM routes) and Windows Access Tokens & UAC.

Always start with enumeration

Privilege escalation is an enumeration problem first. Automated enumerators (WinPEAS, PrivescCheck, Seatbelt) and the built-in commands (whoami /priv, whoami /all, systeminfo) surface the misconfigurations below. The single most important line is often whoami /priv — a dangerous privilege there is frequently a direct path to SYSTEM.

The recurring theme: writable + privileged

Scan the list and the pattern is clear — every route is some privileged execution path (a service, a task, a DLL load, an installer policy) whose inputs a lower-privileged user can write. The attacker's work is enumeration to find the overlap; the fix is to remove it. This is why privilege escalation hygiene is mostly about permissions and least privilege, not patching.

Credentials left lying around

Separately from misconfigurations, Windows hosts accumulate secrets: answer files from deployment (Unattend.xml, sysprep.inf), Group Policy Preferences passwords (the infamous reversible-encrypted cpassword), saved RDP/credential-manager entries, PowerShell history, and config files. Harvesting these often skips escalation entirely by handing you a higher-privileged credential — overlapping with Windows Credential Storage.

Detection and hardening

  • Fix the ACLs: service binaries, service configuration, scheduled-task files and their directories should not be writable by standard users; audit with the same enumerators attackers use.
  • Quote service paths and remove writable PATH directories.
  • Disable AlwaysInstallElevated; never ship GPP passwords.
  • Least privilege for service accounts; prefer virtual or managed service accounts and avoid granting SeImpersonatePrivilege broadly.
  • Telemetry: new/modified services and scheduled tasks, service binary replacement, and MSI installs by non-admins are all high-signal events — see Logging & Telemetry.
